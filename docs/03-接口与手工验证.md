# 接口与手工验证

> 以下手工请求与脚本尚未执行。2026-10-04 单元测试、vet/build 已通过，未启动 Docker 或真实数据库；详见 [完善记录](06-完善记录与验收.md)。

所有业务接口需要 `X-API-Key: local-upload-key`。Key 在服务端绑定 `demo-tenant`，接口不接受客户端传入租户作为授权依据。所有时间使用 UTC RFC3339。

## 1. 初始化上传

`POST /api/v1/uploads`，JSON：

```json
{
  "filename": "sample.bin",
  "size": 1048577,
  "chunkSize": 1048576,
  "sha256": "原始整个文件的64位小写十六进制SHA256"
}
```

201 返回会话信息，含 `id`、`filename`、`size`、`chunkSize`、`totalParts`、`sha256`、`status`、`createdAt` 与 `uploadedParts`。文件名最多 255 字节，拒绝控制字符。文件名仅展示元数据，可以有空格或汉字，不参与存储路径。

默认最大文件 4 GiB；分片大小 64 KiB～16 MiB；总片数最多 10,000；空文件不在当前协议范围。SHA-256 必须为 64 位十六进制，服务端统一为小写。

## 2. 上传分片

`PUT /api/v1/uploads/{id}/parts/{partNumber}`，正文为原始字节，不是 multipart/form-data。片号从 1 开始。可附 `X-Chunk-SHA256`，提供时必须与收到的字节匹配。

201 表示新分片提交，200 表示同内容幂等重试。响应包含 `partNumber`、`size`、`sha256` 和 `alreadyExisted`。服务端计算的哈希始终被保存，不提供分片哈希头也不代表跳过整体完整性检查。

同片不同内容、会话已结束返回 409。短片、超长片、非法片号或非法哈希返回 400。服务端收到完整 staging 后才发布，客户端应只把成功响应或状态列表中的片视为成功。

## 3. 查询与续传

`GET /api/v1/uploads/{id}` 返回会话及已提交 `uploadedParts`，每项包含 `partNumber`、`size`、`sha256`。客户端计算 `1..totalParts` 的差集重传缺片。状态列表只代表数据库已提交的分片，不列出仍上传中的请求。

`scripts/demo.ps1` 支持 `-UploadId`，可继续一个已存在会话；它验证本地文件的整体大小与哈希是否匹配原声明，以避免误用另一个文件继续同一会话。当前不持久化客户端进度文件，需要保留脚本输出的 UploadId。

## 4. 完成

`POST /api/v1/uploads/{id}/complete`，无正文。成功返回状态为 `COMPLETED` 的会话及 `downloadPath`。缺片或会话取消返回 409；分片磁盘缺失返回存储错误；分片或整体哈希失败返回 422。整体哈希错误时应取消并用正确文件重新初始化，当前不支持修改声明或覆盖已提交分片。

完成重复调用返回同一会话；原请求响应丢失可以重试。如果发生数据库提交错误，服务端返回 500，客户端通过 GET 确认状态，再按状态决定重试。

## 5. 下载

`GET /api/v1/files/{id}`、`HEAD /api/v1/files/{id}`。只允许已完成、属于当前租户的文件。响应含 Content-Disposition、ETag 与内容长度。示例：

```powershell
Invoke-WebRequest -Uri http://localhost:8092/api/v1/files/UPLOAD_ID `
  -Headers @{ 'X-API-Key'='local-upload-key'; Range='bytes=0-99' } `
  -OutFile .\first-100-bytes.bin
```

预期 206 和 100 字节正文。下载断点由 Range 表示，与上传分片协议是两套机制。HEAD 用于查询元信息而不获取文件正文。Range 行为由 Go 标准库 ServeContent 处理。

## 6. 取消

`DELETE /api/v1/uploads/{id}`。未完成会话进入 `CANCELED`，完成会话返回 409。响应为 `{"upload": {...}, "cleanupPending": false}`。重复取消幂等，并再次尝试清理残留分片目录。若逻辑取消成功但磁盘清理失败，`cleanupPending` 为 true，状态仍保持取消；没有把清理失败解释为可继续上传，也不向客户端暴露底层文件路径。

## 7. 状态码与验证清单

| 场景 | 应观察到的结果 |
| --- | --- |
| 无 Key / 错误 Key | 401 |
| 正常三片，乱序上传 | 每片提交成功，最终按 1、2、3 合并 |
| 完整倍数文件 | 没有额外零字节末片 |
| 最后一片长度错误 | 400，不列入 uploadedParts |
| 相同片号相同内容重试 | 200，只有一条分片记录 |
| 相同片号不同内容重试 | 409，原内容保留 |
| 演示中断后用 UploadId 续传 | 已提交分片跳过，仅上传缺片 |
| 缺少一片直接完成 | 409，状态不变 |
| 整体 SHA-256 声明错误 | 422，不可下载 |
| 已完成再次完成 | 200，同一个 downloadPath |
| 已完成继续上传或取消 | 409 |
| 取消后继续上传 | 409 |
| PUT 与 cancel 同时执行 | 取消后不允许发布新的元数据 |
| 两个 complete 同时执行 | 串行，最终一个完成结果 |
| GET Range bytes=0-99 | 206，正文 100 字节 |
| Range 超出文件 | 416 |
| HEAD | 无正文，正确长度与 ETag |
| 不合法随机 ID / 不存在 ID | 400 / 404，不能访问路径 |
| 完成文件被管理员删除 | 下载返回存储错误，不把缺失当空文件 |

后续本地验证可执行 `go test ./...`、`go vet ./...`；并发和故障场景还要结合真实 PostgreSQL 与磁盘验证，纯单元测试不能证明跨资源一致性。测试结果另行记录。

## 演示脚本参数

```powershell
pwsh -File .\scripts\demo.ps1 -FilePath C:\data\movie.mp4
pwsh -File .\scripts\demo.ps1 -FilePath C:\data\movie.mp4 -UploadId 已存在ID
```

脚本默认分片 1 MiB，逐片读取，最多在内存保存一片。它不等于高性能客户端，不自动多线程；服务接口接受乱序和并发提交，待测试后可再实现并发客户端。
